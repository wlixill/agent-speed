# Agent Speed — Ubuntu 视觉版

面向 **Ubuntu 22.04 / GNOME / X11 / x64** 的本地 AI 工具仪表，默认保留已有的 Codex 来源配置，可自行启用其他来源。本版沿用原项目的测速核心与 13 种载具素材，加入发光表盘、载具动画、实时曲线，以及独立的完整历史统计窗口。生成中的速度使用近期实测速率估算，完成后校正；并行会话和子 agent 由同一套核心去重、汇总。

## 安装 Debian 包（推荐）

当前 Debian 修订版为 **1.4.1-8**。把 `agent-speed_1.4.1-8_amd64.deb` 复制到 Ubuntu 22.04 x64 桌面机，在该文件所在目录执行：

```sh
sudo apt install ./agent-speed_1.4.1-8_amd64.deb
```

随后在应用菜单中搜索 **Agent Speed** 启动，也可以执行 `agent-speed --dashboard`。
安装包内包含 .NET 运行时，无需安装 SDK；缺少的系统库由 APT 解决，需要时会联网下载。
程序安装在 `/opt/agent-speed`，菜单入口和图标放在标准的 `/usr/share` 位置。
目标会话为 GNOME/X11（登录时选择 Ubuntu on Xorg）；若托盘不可见，请确认 Ubuntu AppIndicators 扩展已启用。

卸载使用 `sudo apt remove agent-speed`，各用户已有的设置与用量历史会保留。

## Codex Radar 平台兼容（1.4.1-8）

当前雷达 API 会拒绝 `client.platform=Linux`。在“上报、头像与设备 → 上报平台标识”中可明确选择 **Windows（兼容模式）**，注册、实时报告和请求标识统一使用 Windows 10；该选择只影响当前上报服务，实际 Ubuntu 系统和本地测速不变。新身份默认仍使用 Linux，清除身份后也恢复原生标识。

兼容选择保存在当前设备身份中，保留设备 ID、密钥、昵称与已选分享项目，重启后继续采用。界面显示当前模式、最近请求 HTTP 状态／错误码／字段、报告尝试和成功次数；不会把请求正文、签名或 API 密钥放入诊断信息。

本次用既有设备身份和真实本机活动完成了注册、两份成功实时报告，以及公开实时榜本人在线记录的验证。没有使用合成用量，也不会补传开启前的本地历史。其他机器安装后仍需自行配置服务、选择兼容模式并同意分享内容，安装包不包含本机身份或密钥。

## 进一步对齐的前四项（1.4.1-7）

- **费用口径**：在设置中标记包月订阅来源，可排除或重新计入汇总显示费用。实时仪表与顶栏可切换 token／费用主读数，各悬浮窗独立选择；热度仍依据 token 速率。订阅排除只影响金额，token、请求数和原始 USD 导出不变。历史有独立的“计入订阅”选项，单独选择订阅来源时仍可查看 API 等值费用。
- **历史交互**：多来源彩色堆叠、来源／模型占比、按日→来源→模型下钻，每日明细排序和复制，流量镜像图与每日收发量；CSV 额外包含所选币种换算列、流量列与覆盖标记，未知值保留空白。
- **悬浮窗高级操作**：拆分、合并、撤销、自动排布、窗间吸附与对齐。每窗可独立设置输出／总量刻度、费用主读数、流量范围、置顶、空闲淡出及名称显示；跨显示器的位置继续保存。最多八窗，达到上限时拆分保留未展开来源。
- **增强流量采集**：默认不启动提权辅助进程；点击启用后由系统管理员认证。具体覆盖边界见下文网络流量说明。

## 第 9～12 项功能

- **应用更新**：托盘或设置中打开“检查应用更新”。支持 HTTPS 发布清单、SHA-256 校验、Debian 包名称／架构／版本检查，下载后由 PackageKit 安装，再从窗口重启新版。也可选择本地 deb；管理员认证由系统处理。自动检查默认关闭，不会自动安装。
- **更新源配置**：此 Ubuntu 分支没有已发布的公共更新服务，需在设置中填写自己的 HTTPS 清单地址。打包时生成 `dist/agent-speed-linux-release.json`；将清单与 deb 放在同一 HTTPS 目录即可使用。清单中的相对 `debUrl` 会相对于清单地址解析；包必须与清单同源。未配置时可以继续手动安装或在应用中选择本地 deb。
- **网络流量**：可选择无特权 TCP 基础采样，或在设置中点击“启用增强流量采集”，由系统认证后观测当前用户 IPv4/IPv6 TCP 与 UDP 成功收发的应用字节，覆盖常规 send/sendmsg/read/write 与采样间已关闭连接。增强模式需要内核 BTF、kprobe 和允许 BPF 的内核策略；不可用时保留基础模式。它不读取通信内容、远端地址或端口，不统计协议报文头，`MSG_PEEK` 不重复计数；`sendfile/splice/io_uring` 等路径尚未逐项验证；因此仍是有明确覆盖范围的观测量。停止采集或退出应用即结束提权辅助进程，不安装常驻服务。会话无法证明归属时保留未归属，计数缺失显示未知；模式切换不会重复累计。
- **流量显示与历史**：每个悬浮窗可选自身来源、整机或关闭流量；顶栏可显示独立的上传／下载数字图标，选择字节／比特单位和工具子进程口径。流量还整合到用量历史的镜像柱图、每日明细及 CSV，独立流量窗口继续保留。旧历史与不同采集模式混合的日期使用保守的观测标记；开启前的日期留空。整机网卡默认优先物理接口，虚拟接口回退会提示可能重复。本机网卡和不完整的进程观测量不冒充完整 agent 流量上报。
- **悬浮窗与主题**：管理窗口提供 LED、指针、液体、反应堆、极简五种表盘，最多八个独立悬浮窗。每个可选择来源、指标、样式、尺寸、透明度、穿透和位置。支持九组预设称号、最多八组自定义称号，以及跟随全局主题；已有单悬浮窗自动迁移。
- **多来源**：“工具来源与路径”可启用 Codex、Claude Code、Claude Desktop、DSH、OpenCode、Gemini CLI、omp、Antigravity、WorkBuddy、WorkBuddy AI、ZCode、Kimi Code CLI、Grok Build，并设置各自日志根目录。沿用 Core 解析器；只读取当前用户可以访问的文件。Claude Code 与 Claude Desktop 共用同一个 Claude 根目录。历史可按来源筛选，模型统计与 CSV 保留来源归属。默认不扫描其他来源；关闭来源不删除数据库中的已有汇总，重新开启可继续查看。
- **可选上报与设备资料**：托盘打开“上报、头像与设备”，填写兼容 Report API 的 HTTPS 服务地址，发现能力后选择上报内容并明确同意。支持签名设备注册、暂停／关闭／请求遗忘，以及服务支持时的资料、头像、身份与设备配对。默认关闭，没有预设服务器；不提供这些能力的服务会明确显示不支持。默认使用 `Linux` 平台标识，也可明确选择上文的 Windows 兼容模式。自动化测试使用模拟服务；真实雷达验证需单独显式运行，不会随测试或安装发送本机用量。

## 第 5～8 项功能

- **价格与费用**：实时与历史共用价格表，面板和悬浮窗显示当前每秒 API 等值费用；设置中可选人民币等 38 种币种，历史金额与费用图表同步换算。CSV 保留明确的 USD 原始费用，便于复算。
- **公开价格与汇率更新**：默认离线，在设置中启用后可立即检查，并按原项目规则每天更新；模型价格只接受有效的新版本，汇率使用已校验数据或内置／缓存参考值。设置显示实际采用的价格版本、汇率日期、来源、过期和错误状态。未知费用显示 `—`，部分已知显示 `≥`，估算显示 `≈`，不代表订阅账单。
- **顶栏数字**：通过 AppIndicators 的真实图标显示紧凑速度数字（K/M/G），估算带 `≈` 标识，最多每秒更新；悬停显示完整精度，可在设置中切回普通图标。
- **主题与动画**：支持浅色、深色、跟随系统；可选关闭／柔和／标准／全开特效，支持减弱动态效果，并遵循 GNOME 关闭动画的设置。关闭特效或减弱动态效果时停止持续载具运动，读数仍更新。
- **执行模式**：面板分开显示实际记录与配置默认值；历史新增执行模式页签、维度选择及当前维度 CSV。配置为 Fast 不会被写成已实际使用 Fast；日志缺少证据时显示未知，也不会按速度或模型名猜测。

公开数据更新仅下载模型价格和汇率，不上传本机用量、对话、目录或命令。关闭更新会取消进行中的请求并使用现有参考数据。应用自身的更新入口与公开价格更新分别配置，见第 9～12 项。

## 第 1～4 项功能与使用说明

- 仪表和悬浮窗以 `≈` 明确标记历史参考估算，另外显示最近完成请求的 token、耗时和记录时间；耗时包含首 token 等待。现有 rollout 记录没有逐 token 时间戳，不能将估算值当作当前屏幕出字流速。无有效参考时显示 `—`。
- 实时仪表可切换“输出速度”和“输入＋输出吞吐量”，两种指标各自保存表盘刻度；输入包含缓存。历史平均速度仍明确按输出 token 计算。
- 面板列出全部近期 agent，超出窗口可滚动查看；生成、工具调用、空闲及子 agent 信息继续保留。
- “设置”里可选择登录自动启动与后台启动，默认不开启登录启动；普通启动按设置决定是否打开面板，应用菜单总是打开面板。`agent-speed --background` 可强制后台启动，`--dashboard` 可显式打开面板。后台重复启动不会将正在运行的面板弹到前台。
- 悬浮窗支持尺寸、不透明度、鼠标穿透、边缘吸附，按显示器布局保存相对位置。启用穿透后，从托盘选择“恢复悬浮窗鼠标操作”可关闭；尺寸和穿透设置在隐藏／显示后仍生效。
- “用量历史 → 模型统计”增加输入 token、缓存读取 token、模型名称筛选、排序和模型 CSV 导出。
- 数据读取状态展示生效目录、会话数与最近日志活动时间；设置窗口可导出包含版本与数字用量的诊断 JSON，不含对话正文、工具命令、会话名或项目名。

升级会迁移历史库并补充模型输入量：尚在磁盘上的原始记录会重新分析；原始记录已删除时保留已有汇总，无法确定的模型输入／缓存量显示 `—`，不会按来源总量分摊或伪造零值。首次升级分析可能比平时久。

## 直接运行

解压 `AgentSpeed-Ubuntu-linux-x64.tar.gz`，进入解压目录：

```sh
./AgentSpeed.Linux --dashboard
```

发行包包含 .NET 运行时，无需安装 SDK。保持解压目录完整，也可运行包中的 `launch.sh` 启动。

- 默认读取 `$CODEX_HOME/sessions` 或 `~/.codex/sessions`，以及相邻的 `archived_sessions`；支持压缩记录。
- 悬浮窗带彩色发光刻度和载具动画，可拖动并按屏幕布局记住位置；双击打开紧凑实时仪表，右键打开菜单。
- 紧凑实时仪表显示已启用来源的速度、载具称号、会话和今日统计。曲线可切换 1、2、5 分钟，区分实测部分与生成中的估算部分。
- 载具使用原项目的 13 种素材，从步行、自行车、汽车到飞机和火箭，随速度变化切换并驱动动画；空闲时降低动画更新频率，隐藏后停止动画更新。
- 实时仪表里的“视觉满量程”默认 **400 tok/s**，可调整显示比例。它只影响热度、称号和载具升级门槛，不改变实测速度、token 数或用量历史。
- 独立的“用量历史”窗口提供今天、昨天、7/30/90 天、今年、全部及自定义日期范围；包含统计卡片和趋势小图、每日柱状图与平均速度线、每日明细、模型统计和 CSV 导出。
- 统计包括输出和输入 token、请求数、按实测时间加权的平均速度，以及可确定的 API 等值费用。费用不代表订阅实际账单；未知值显示 `—`，部分已知费用显示 `≥`。历史峰值只对实际监测过的日期显示。
- 首次历史分析在后台进行，每日汇总落入 SQLite，之后每 30 秒增量刷新。图表没有记录的日期保留空缺，不伪造已测得的零值。
- 托盘可分别打开实时仪表和用量历史、显示或隐藏悬浮窗、退出。关闭面板或历史窗口后继续在托盘运行。
- 默认只启用 Codex，自动检查更新、流量采集、公开数据更新和上报均默认关闭；不保存对话内容。升级保留用户已经开启的选项。

Ubuntu 的 `ubuntu-appindicators@ubuntu.com` 扩展需要启用才能显示托盘；即使托盘不可见，也能在悬浮窗右键菜单中退出。当前版本未验证 Wayland。

## 数据位置

- 设置：`${XDG_CONFIG_HOME:-~/.config}/agent-speed/settings.json`
- 用量历史：`${XDG_DATA_HOME:-~/.local/share}/agent-speed/history.sqlite`
- 流量历史：上述数据目录中的 `traffic-linux.json`。
- 可选上报的设备状态与签名密钥保存在上述数据目录中，文件仅当前用户可读写；备份时不要公开这些文件。
- 视觉版沿用此前版本的数据路径，升级后继续读取已有设置和每日用量汇总。
- 使用 `--data-dir PATH` 时，上述文件都存入指定目录，可用于隔离验证。
- 可用 `--codex-dir /path/to/sessions` 指定本次启动的数据源，也可在设置窗口中更改并保存。
- 不会修改工具的原始记录。便携版删除解压目录即可移除程序；Debian 安装版用 APT 卸载。保留上述用户数据目录即可保留历史。

## 从源码构建

需要 .NET 10 SDK：

```sh
dotnet test windows/tests/AgentSpeed.Core.Tests -c Release
dotnet test linux/tests/AgentSpeed.Linux.Tests -c Release
dotnet run --project linux/src/AgentSpeed.Linux -- --dashboard
bash linux/scripts/publish.sh
bash linux/scripts/package-deb.sh
```

发布到 `dist/AgentSpeed-Ubuntu-linux-x64/`，并生成同名 `.tar.gz`。`linux-arm64` 可作为发布参数，但尚未在 ARM64 实机验证。

Debian 包版本由仓库根目录的 `VERSION` 与 `linux/DEBIAN_REVISION` 组合，当前生成 `dist/agent-speed_1.4.1-8_amd64.deb` 及 SHA-256 校验文件。
增强组件静态包含固定版本 libbpf，不替换宿主机库。除 SDK 外需要 `clang-14`、`gcc`、`make`、`pkg-config`、`libelf-dev`、`zlib1g-dev`、`linux-libc-dev`、`python3`、`dpkg-deb` 和 `desktop-file-validate`（Ubuntu 的 `desktop-file-utils` 包）。
脚本会独立构建，不覆盖正在运行的便携版；也可用 `--publish-dir PATH` 对已经发布的 x64 目录打包。
第三方许可证从构建所用的 NuGet 缓存收集，缓存位置自定义时需设置 `NUGET_PACKAGES`。

图形系统依赖 Ubuntu 桌面的 X11、字体、Fontconfig 和 OpenGL；可用 `--software-rendering` 切换软件渲染。无需安装 Windows 或 Wine。

## 开发验证

```sh
python3 linux/scripts/smoke_test.py dist/AgentSpeed-Ubuntu-linux-x64/AgentSpeed.Linux
python3 linux/scripts/visual-smoke.py dist/AgentSpeed-Ubuntu-linux-x64/AgentSpeed.Linux
python3 linux/scripts/feature-smoke.py dist/AgentSpeed-Ubuntu-linux-x64/AgentSpeed.Linux
python3 linux/scripts/app-feature58-smoke.py
python3 linux/scripts/app-feature912-smoke.py
python3 linux/scripts/history-advanced-smoke.py
python3 linux/scripts/advanced-orbs-smoke.py
deb_version="$(cat VERSION)-$(cat linux/DEBIAN_REVISION)"
python3 linux/scripts/check-deb.py "dist/agent-speed_${deb_version}_amd64.deb"
```

`smoke_test.py` 在临时目录创建明确的合成 Codex 日志，实际启动 X11 界面，追加用量、检查实时测速和历史、重启验证持久化，并保留截图和状态文件。
`visual-smoke.py` 使用独立的 30 天合成历史及持续追加的实时记录，检查原版火箭素材、连续变化的载具画面、实时曲线与历史统计，并保存实时仪表、悬浮窗和历史窗口截图。测试数据不会作为普通使用时的回退数据。
图形验证需要现有 X11 桌面或 Xvfb，不读取用户的真实会话。`check-deb.py` 检查实际安装包的元数据、权限、校验和、运行时、菜单与图标，并在支持的隔离环境中验证解包和卸载。

`app-feature58-smoke.py` 启动实际生产 Application，使用隔离合成记录验证共享价格对象、币种与费用图表、主题、静止动画、执行模式与数字托盘；若本机提供 GNOME StatusNotifierWatcher，会进一步核对真实 D-Bus IconPixmap。需要 .NET SDK，所有数据和配置写入临时目录，不接入真实自启动或真实会话。
